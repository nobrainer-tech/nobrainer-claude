A practical working pattern

Keep the plan clear and the work focused.

Claude Code keeps one MAIN session in charge. When a task can stand on its own, MAIN can assign a focused role, then review the result in context.

SCOUT

Gather the evidence

Use Haiku for a bounded search or fact-finding task. MAIN decides what matters before work continues.

BUILDER

Implement a clear slice

Give Sonnet a defined area and outcome. MAIN integrates the result with the rest of the task.

REVIEWER

Check the acceptance bar

Ask Sonnet to look for missed requirements and concrete defects. MAIN owns the final decision.

Model names are requests, not proof. Provider aliases and account access can differ. Read back the selected model in Claude Code before relying on a role assignment.

Set up Claude Code on your terms.

The installer previews its plan before it writes. It adds a managed block to your user CLAUDE.md and preserves the text around it.

  • Keep your current MAIN model and effort. Choose --opus-main only when you want Opus 5.5 selected as MAIN.
  • Leave auto memory alone by default. Opt in with --enable-auto-memory only when you choose.
  • Keep permission settings as they are. The setup does not enable permission bypass or experimental agent teams.

nobrainer-tech-flow is installed separately and required before this adapter. Follow the exact setup instructions to install it and verify Claude Code discovers its entry point.

Your instructions stay yours

Keep policy and memory distinct.

The managed CLAUDE.md block carries explicit setup guidance. Claude Code's native auto memory is optional and remains unchanged unless you ask to enable it. The installer does not write project MEMORY.md files or import private owner memory.

Backups and guarded restore help you inspect and recover installer-managed changes without replacing later edits.
